# italiano-anki

A small data pipeline that works as the **memory of our Italian lessons**: everything seen in class (sentences, vocabulary, conjugated verbs, songs, texts) is recorded in Postgres, and flashcards are generated automatically as an Anki deck (`.apkg`). Anki handles spaced repetition; the database only holds the content.

## Architecture

```
aulas/YYYY-MM-DD.yaml ──load──▶ Postgres (Docker) ──card views──▶ export ──▶ italiano.apkg ──▶ Anki
   (hand-written)        upsert   lesson, source,      SQL, one per    genanki
                                  sentence, vocab,     card type
                                  verb, conjugation
```

| Decision | Why |
|---|---|
| **Database is the source of truth**; one YAML file per lesson as input and mirror | New lessons are typed in YAML right after class (`load`); corrections are made directly in the database with any SQL client; `dump` rewrites the YAML files from the database, so they stay a plain-text backup and a later `load` never undoes an edit. Round-trip file → DB → file is lossless (tested). |
| **Idempotent load** (upsert on natural keys + delete rows no longer in the file, in one transaction) | Re-running `load` after fixing a typo converges to the same state: no duplicates, no stale rows. |
| **Every fact records its origin**: a lesson, a source (song, text...) or both, enforced by a `CHECK (lesson_id IS NOT NULL OR source_id IS NOT NULL)` and a `UNIQUE NULLS NOT DISTINCT` natural key | Content learned from a song outside class has no fake lesson; the views deduplicate, so a word seen in two places is one card tagged with every lesson date. |
| **Cards generated by SQL views**, one per card type | The card rules (which rows, which deck, front/back layout, tags) are visible and queryable in the database; Python only serializes. |
| **Stable GUID** = hash(card type, natural key of the source content) | Never a database id, so re-importing a corrected deck updates existing cards and keeps their review history instead of duplicating them. |
| **Native Anki Cloze note type** for songs, sentences and conjugations; a custom two-card note type for vocabulary (IT → PT and PT → IT) | Uses what Anki already does well; translation and links go to the extra field. |
| **Postgres bound to `127.0.0.1`**, named Docker volume, credentials in `.env` | Local, zero cost, isolated from other projects; nothing reachable from the network. |

Card types and subdecks:

| View | Deck | Front | Back |
|---|---|---|---|
| `v_card_song` | `Italiano::Músicas` | linked title – artist, line (gap added in Anki) | translation |
| `v_card_sentence` | `Italiano::Frases` | sentence (gap added in Anki) | translation |
| `v_card_vocab` | `Italiano::Vocabulário` | IT word (and a reversed PT card) | translation, part of speech, gender, example |
| `v_card_conjugation` | `Italiano::Verbos` | `andare · passato prossimo · noi: siamo andati` (gap added in Anki) | translation + source |

Every card is tagged with the lesson date (`aula::2026-11-06`).

## Gaps are made by hand in Anki

Sentences and song lines are stored **without** gaps: not every automatic gap makes sense,
so they are chosen in Anki. They are exported as native Cloze notes with no deletion yet
(Anki shows a "no cloze found" notice), and the gap is added in the Anki browser
(select the word, `Ctrl+Shift+C`). This applies to every card type except vocabulary,
which is a plain two-way card.

Because the gaps live only in Anki, re-import new decks with
**Existing notes → Never update** (*Notas existentes → Nunca atualizar*): new cards are added,
hand-made gaps are kept.

## Privacy

Real lesson content (including song excerpts, kept short and for personal study only) never enters the repository: `aulas/*` (except the fictional `aulas/exemplo.yaml`), generated `.apkg` files and `.env` are git-ignored, and the data lives only in a local Docker volume.

## How to run

Requirements: Docker Desktop, Python 3.11+.

```powershell
copy .env.example .env            # then set a password
docker compose up -d --wait       # Postgres on 127.0.0.1:5433
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"

python -m italiano load aulas\exemplo.yaml   # or: load aulas  (every lesson except the example)
python -m italiano export                    # -> output\italiano.apkg
python -m italiano dump                      # database -> aulas\*.yaml (after editing in a SQL client)
python -m italiano remove 2000-01-01         # delete a lesson (e.g. the example)
pytest
```

### Editing the database directly

Connect any client (e.g. DBeaver) to `127.0.0.1:5433` with the credentials in `.env`, edit the tables, then:

```powershell
python -m italiano dump      # keep the YAML mirror in sync
python -m italiano export    # rebuild the deck
```

To add a row by hand, set `lesson_id` and/or `source_id` (at least one is required). `tags` is an array: `{saluti,presente}`.
The card views (`v_card_*`) show exactly what will be exported, so they double as a preview.

In Anki: *File → Import* → `output/italiano.apkg`. Re-importing after changes updates cards in place.

## YAML format

Only `date` is required. See [`aulas/exemplo.yaml`](aulas/exemplo.yaml) for a complete example.

```yaml
date: 2026-11-06
title: Prima lezione
notes: free text

sources:                     # song | text | video | exercise
  - key: my-song             # stable id; reuse it when the source comes back
    kind: song
    title: Song title
    author: Artist
    url: https://...
    lines:
      - it: a line of the song
        pt: its translation

sentences:                   # sentences from class
  - it: Mi chiamo Giulia.
    pt: Meu nome é Giulia.
    tags: [presentarsi]

vocab:
  - it: finestra
    pt: janela
    pos: noun
    gender: f                # m | f | m/f
    example: Apri la finestra.
    source: my-song          # optional: where the word was seen

verbs:
  - infinitive: andare
    pt: ir
    source: my-song          # optional: where these forms were seen (shown on the card's back)
    conjugations:
      passato prossimo:      # tense -> person -> form
        noi: siamo andati
```

### Source files

Content that comes only from a source (no lesson) lives in `aulas/fontes/<key>.yaml`.
A file with `key` instead of `date` is a source file; every row in it belongs to that source.

```yaml
key: my-song
kind: song
title: Song title
author: Artist
url: https://...
lines:
  - {it: a line of the song, pt: its translation}
vocab:
  - {it: finestra, pt: janela}
verbs:
  - infinitive: bere
    pt: beber
    conjugations: {presente: {io: bevo}}
```

`load aulas` loads `aulas/fontes/*.yaml` first, then the lessons; `dump` writes both.

italiano/            CLI: lesson_file (parse/validate), loader (upsert), dump, exporter (genanki), guid
